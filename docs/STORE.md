## Before submitting

1. Run the full QA pass in `docs/QA-CHECKLIST.md` on a clean Chrome profile.
2. Confirm the final version in `manifest.json` and `package.json`.
3. Capture five store screenshots (1280×800 or 640×400) and a 440×280 promo
   tile if desired. Do not show personal browsing data.
4. Verify the privacy policy URL is live if you provide one. The bundled page is
   also reachable from the library footer.
5. Create a public support/contact URL or use <https://madwolfstudios.com/>.
6. Decide the donation URL. Replace `TODO: ADD DONATION LINK` everywhere only
   with a verified destination.
7. Make the GitHub repository public and confirm the README has no dead release
   links.
8. Build the final ZIP from a clean checkout:

   ```sh
   npm.cmd ci
   node --test
   node scripts/package.mjs
   ```

9. Upload the ZIP from `release/`, not `dist/` directly.

### Permission justifications

The store asks for a justification per permission:

- **`activeTab`** — Required to read the title and URL of the current tab after
  the user clicks the CofreTabs toolbar icon, so that the requested page can be
  shown in the save preview. The extension does not access tabs at any other
  time.
- **`scripting`** — Required to inject the slide-over save panel into the active
  tab after that same explicit click. No content script runs automatically.

There are **no host permissions** and no remote code.

### Data usage answers

Use these answers only if they match the final code and policy:

- Does the extension collect personally identifiable information? **No.**
- Does it collect health, financial, authentication or personal communications
  data? **No.**
- Does it collect location, web history or user activity? **No** — the extension
  reads only the current tab's title/URL after a click and stores it locally; it
  does not collect or transmit browsing history.
- Does it sell or transfer data to third parties? **No.**
- Is data used for purposes unrelated to the single purpose? **No.**
- Is data used to determine creditworthiness or for lending? **No.**
- Does it use remote code? **No.**
- Is all data stored locally? **Yes**, in IndexedDB, unless the user exports a
  backup file.

If the store's questionnaire treats locally stored user-chosen URLs as "web
history", disclose it accurately as **stored locally, not transmitted**, and
point to the privacy policy. Do not claim "collects nothing" if the form defines
local storage as collection.

### Single purpose statement

> CofreTabs lets a user explicitly save the current tab into a private, local
> vault, then search, organize, restore and back up those saved tabs.

### Remote code declaration

No remote code is used. All JavaScript, CSS, icons and the Public Suffix List
are packaged in the extension.

## Privacy policy URL

## Versioning and release steps

1. Bump `version` in `manifest.json` and `package.json`.
2. Add `docs/RELEASE-NOTES-v<version>.md` and a CHANGELOG entry.
3. Run tests, build and package.
4. Tag the commit (`git tag -a v<version> -m "CofreTabs v<version>"`).
5. Upload the ZIP in the developer dashboard.
6. Complete the privacy questionnaire and permission justifications.
7. Submit for review.
8. Only after approval, update the README/release links and announce.

## Common rejection risks

- Claiming "no data collection" while the form counts local storage as
  collection. Answer precisely.
- Requesting broader permissions than needed. Keep `activeTab` + `scripting`.
- Broken privacy policy URL. Verify it.
- Screenshots showing a different UI than the submitted build.
- Missing or misleading donation/store links. Do not ship placeholders in a
  public listing; replace or remove them.
- Remote favicon fetches. The code intentionally does not do this.
